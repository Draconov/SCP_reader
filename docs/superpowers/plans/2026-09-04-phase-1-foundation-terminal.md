# SCP Research Terminal Phase 1 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [x]`) syntax for tracking.

**Goal:** Build a complete, publishable Phase-1 SCP Foundation Research Terminal repository for GitHub Pages with local researcher IDs, a desktop/mobile workstation, real SCP Wiki archive synchronization, search/reading/notes/bookmarks, terminal commands, settings, and offline caching.

**Architecture:** A dependency-free TypeScript static application loads normalized archive JSON generated by a Node sync CLI. Researcher state is isolated in IndexedDB with a localStorage fallback and portable through versioned `.scp-id` JSON. GitHub Actions validate, synchronize selected real SCP Wiki records, build, test, and deploy the static site.

**Tech Stack:** TypeScript, native browser DOM APIs, IndexedDB, Node 22 test runner/tooling, GitHub Actions, static GitHub Pages.

**Spec:** `docs/superpowers/specs/2026-09-04-scp-research-terminal-design.md`

**Execution note:** The approved design selected React/Vite. The implementation sandbox could not reach the npm registry, so Phase 1 was implemented with dependency-free TypeScript + native DOM/browser APIs while preserving the approved domain boundaries, static GitHub Pages model, UI behavior, and migration-friendly module structure. This avoids shipping code that could not be built or verified in-session.

## Global Constraints

- Repository name: `SCP_reader`.
- GitHub Pages only; no runtime backend or user account system.
- Canonical SCP Wiki material and simulation metadata remain separate.
- Researcher state remains local and exportable as human-readable `.scp-id` JSON.
- Desktop uses a workstation shell; mobile uses a dedicated Field Terminal shell.
- Interface modes: Modern, Foundation Hybrid, Physical CRT, Legacy Terminal, Archive Terminal.
- Immersion levels: Low, Standard, Full.
- Previously opened archive records are cached automatically for offline reading.
- Real SCP Wiki content is synchronized by tooling; do not hand-author canonical article text into simulation source.
- Attribution metadata is first-class and exposed in the reader.
- No anti-cheat.
